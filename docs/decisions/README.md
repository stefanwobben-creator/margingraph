# Decisions (ADRs)

Documents describe **what is true now**. ADRs record **why it changed** — the context, the
options, and what we knowingly gave up.

## When to write one

Write an ADR when a decision is expensive to reverse, when it changes a `stable` document,
or when a future engineer or agent would reasonably ask "why on earth is it like this?".

Do not write one for reversible, low-stakes choices.

## Process

1. Copy `0000-template.md` to `NNNN-short-title.md` (next free number).
2. Open it as `proposed`.
3. When accepted, set the status and update the affected documents in the same change-set.
4. Superseding an ADR never edits the original — write a new one and link both ways.
